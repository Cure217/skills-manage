# Article Summary

## 何时使用

当用户提出以下需求时使用本 Skill：

- “帮我总结这篇文章”
- “把这篇博客提炼一下”
- “总结这个网页 / 公众号 / 长文”
- “帮我把这篇文章做成读书笔记 / 要点清单 / 分享提纲”
- “基于这篇文章写一版公众号风格整理稿”

支持的常见输入：

- 网页 URL
- 用户直接粘贴的文章正文或摘录
- 本地 `Markdown / TXT / PDF / DOCX / HTML`

## 不适合的场景

- 总结当前聊天：使用 `summarize-current-conversation`
- 把对话整理成 HTML 页面：使用 `conversation-html-summary`
- 总结 B 站视频：使用 `bilibili-video-summary`
- 汇总 AI 新闻资讯：使用 `daily-ai-news`

## 默认工作流

1. 先判断文章来源。
   - 如果是网页文章，先提取正文、标题、作者、发布时间和来源。
   - 如果是本地文件，按格式选择工具：
     - `PDF / DOCX / HTML`：优先参考 `references/source-handling.md`
     - `Markdown / TXT`：可直接读取
   - 如果用户只提供片段或摘录，明确说明“基于提供片段总结”。
2. 再判断输出粒度。
   - 用户说“快速看懂 / 一句话 / TL;DR”时，使用简版。
   - 用户说“总结一下 / 梳理一下”时，使用标准版。
   - 用户说“深度总结 / 提炼框架 / 做分享稿”时，使用深度版。
   - 用户说“改写成公众号风格 / 长文整理版”时，使用改写版。
3. 提取核心信息。
   - 文章主旨是什么。
   - 核心观点有哪些。
   - 论证结构如何展开。
   - 有哪些关键事实、数字、案例或引用。
   - 对读者的启发、行动建议或适用人群是什么。
4. 显式处理不确定性。
   - 如果没拿到全文，不要假装总结了全文。
   - 如果来源信息不完整，明确标注“作者 / 日期未确认”。

## 输出要求

- 默认优先输出中文。
- 先给一句话结论，再给结构化要点。
- 除非用户明确要极简版，否则默认使用“标准版”。
- 如果用户要固定模板，查看 `references/output-formats.md`。

标准版默认建议包含：

- 一句话总结
- 核心观点
- 结构拆解
- 关键细节 / 数据 / 案例
- 适合谁看
- 可执行启发

## 约束

- 不要编造文章中不存在的观点、数据、引用和作者背景。
- 没读到全文时，不要写成“全文总结”；要明确说明是基于摘要、摘录或可见部分。
- 如果文章明显偏观点表达，区分“作者观点”和“客观事实”。
- 如果用户要求改写版，允许提高可读性和结构感，但不要伪造成原文逐字复刻。
- 如果用户给的是受版权保护内容的片段，优先做摘要、提炼和改写，不长段复述原文。

## 何时读额外文件

- 如果来源是网页 / 本地文件的不同格式处理方式，读 `references/source-handling.md`
- 如果需要固定输出模板，读 `references/output-formats.md`

## 自检

- 是否说明了总结范围：全文 / 摘录 / 片段 / 文件？
- 是否保留了文章最重要的主旨、结构和关键论据？
- 是否把“事实”“作者观点”“我的整理”区分清楚？
- 如果用户要的是改写版，是否明确这不是逐字稿？
